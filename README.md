# TOMA推し活部 — はじめてのとおま案内

總水とおまさんを応援する非公式ファンコミュニティのサイトです。生成り・ネイビー・淡い紫を基調に、スマートフォンでも読める構成にしています。

Cloudflare Pages用のHTMLと、YouTube・ブログの情報を取得するWorkerを同梱しています。生成にはNode.js 20以上と、HTMLの翻訳処理用のparse5を使用します。初回は `npm ci` で依存パッケージを準備してください。本番サイトは https://toma-oshikatsubu.pages.dev/ です。ソースは [GitHub](https://github.com/morikyun/toma-oshikatsubu) で管理します。PRの確認用サイトをチェックし、運営者がmainへマージすると、GitHub Actionsから現在のCloudflare Pagesへ公開します。初回設定・操作方法は [Issueから確認・公開まで](docs/GITHUB_WORKFLOW.md) を参照してください。

## 日本語・英語・中国語（簡体字／繁体字）

日本語は従来のURL、英語は `/en/`、簡体字中国語は `/zh-hans/`、繁体字中国語は `/zh-hant/` 以下に生成します。全ページのヘッダーに言語選択のプルダウンを表示し、同じページ・用語へ切り替えられます。選択肢は「日本語 / English / 简体中文 / 繁體中文」です。通常のURLから開いたときはブラウザーの優先言語の順に対応言語を選び、対応言語がなければ英語を表示します。中国語はzh-CN・zh-SGを簡体字、zh-TW・zh-HK・zh-MOを繁体字に対応づけ、zh-Hans・zh-Hantの明示指定を優先します。

手動で選んだ言語は同じタブのsessionStorageに保存し、その後の閲覧で維持します。Cookieは使用しません。保存できない場合はURLのlangパラメーターで選択を引き継ぎます。明示的な言語URL（/en/など）はその言語で開けるため、各言語のページを共有できます。JavaScriptが無効な場合は各言語へのリンクを表示します。今後は `public/assets/locales.js` への言語追加と翻訳JSONの追加で、選択肢を増やせます。

本文・61語の用語集・検索・絞り込み・入部案内・プライバシーポリシーを各言語に翻訳しています。中国語の固有人名・作品名、YouTube動画・ブログ記事・ライブの原題、チャンネル名は元の表記を残します。簡体字では「视频」、繁体字では「影片」など、それぞれの表記・用語を使用します。外部のフォームやリンク先、動画そのものは翻訳しません。自動更新は全言語で同じAPI・キャッシュを共用し、更新間隔やAPIキー・KVの設定は従来どおりです。

翻訳は `content/i18n/` の `ja.json`・`en.json`・`zh-Hans.json`・`zh-Hant.json` で管理します。`messages` は本文、`runtime` は自動更新後の確認文・件数・日付などです。日時は全言語で日本時間を維持します。日本語本文は従来の `content/`・`src/pages.mjs` 等を編集し、次の手順で翻訳を揃えます。

1. `npm run i18n:sync` を実行して日本語の対照表を更新します。`ja.json` の本文は自動抽出するため、直接編集せず元の文章を変更してください。
2. `research/i18n-pending.json` で追加・変更された文章と未訳の言語を確認し、各言語JSONの同じキーに訳を入れます。`{date}`・`{count}` 等の差し込み項目は残してください。
3. `npm run build`・`npm run check`・`npm test` で確認し、`npm run package` で公開用ZIPを更新します。

日本語本文が変わると新しいキーになるため、古い訳をそのまま流用しません。未訳があれば生成を停止します。既存の訳のみを直す場合は該当言語のJSONを編集して再生成します。検索は閲覧中の言語と日本語に対応し、用語のアンカーIDは共通です。各言語のcanonical・hreflang・サイトマップも生成します。

## プライバシーとYouTubeの表示

`/privacy/` にプライバシーポリシーを追加し、全ページのフッターに「プライバシーポリシー」を設置しています。サイト運営者は「TOMA推し活部 IT部部長 もり かずひろ(もりきゅん)」、問い合わせ先は指定のGoogleフォームです。入部フォームの回答・YouTube掲載申請は発起人の蓮さんが管理し、退部・不掲載時はFacebook Messengerで蓮さんへ連絡する運用を記載しています。保存期間の指定は受けていないため、一律の自動削除期限は記載していません。

YouTubeの動画情報・サムネイル・配信予定は、ページを開くと表示します。直近の公式動画は `youtube-nocookie.com` の埋め込みプレーヤーを直接読み込み、自動再生はしません。確認済みの情報をHTMLに含め、JavaScriptで最新情報を取得します。画面外の画像・プレーヤーは遅延読み込みを利用します。

表示の同意ボタン、表示設定画面、localStorageの選択処理は廃止しました。以前の「表示しない」や期限切れの設定がブラウザに残っていても参照しません。YouTubeの4つのAPIルートは通常のGETで取得でき、特別な同意ヘッダーは不要です。APIキーは引き続きサーバー内だけで使用します。公式動画・配信予定の4時間キャッシュとファン動画の30分キャッシュは維持しています。

プライバシーポリシーには、閲覧に伴う外部サービスとの通信、Cookie等、問い合わせ先を説明し、YouTube利用規約とGoogleのプライバシーポリシーへのリンクを残しています。埋め込みの接続先は [YouTube公式ヘルプ](https://support.google.com/youtube/answer/171780?hl=ja) に従い、CSPでも `https://www.youtube-nocookie.com` のフレームを許可しています。

### 外部フォーム側で行うこと

サイトの更新だけでは、Formzu・Googleフォームの説明欄は変わりません。今回のZIPを公開した後、各フォームにも利用目的とポリシーURLを記載してください。追記用の例：

- 入部フォーム：入力された情報は、入部手続き、参加先の確認、連絡、グループ活動への案内に利用します。TOMA推し活部のプライバシーポリシー：https://toma-oshikatsubu.pages.dev/privacy/
- お問い合わせフォーム：入力された情報は、お問い合わせへの回答と、必要な確認・連絡に利用します。TOMA推し活部のプライバシーポリシー：https://toma-oshikatsubu.pages.dev/privacy/

Cloudflareの管理画面のCookie・ログ設定や外部フォームの管理権限は、この実装作業では変更していません。アクセス解析等を追加する場合は、実際の情報の送信に合わせてポリシーと設定を更新してください。

## 直近のYouTube配信

`/schedule/#recent-youtube` に「直近のYouTube配信」を追加し、配信予定欄のすぐ後に掲載しています。公式2チャンネル各1本の最新公開済み動画を、プライバシー強化モードの埋め込みで表示します。通常動画と終了済みの配信が対象です。ページの閲覧に合わせて読み込み、自動再生は行いません。埋め込み不可の動画や再生できない環境でも、YouTubeへ直接進めるリンクを残します。

`/api/official-latest` は2本の公開RSSから候補を取得し、RSSの `/shorts/` URLを除外したうえでYouTube Data APIの `videos.list` で公開状態・終了済み状態・埋め込み可否を確認します。公開前、配信中、非公開、限定公開、未来の公開日は含めません。検索APIは追加で使用せず、通常は1回の動画詳細取得にまとめます。公式の最新動画も4時間のキャッシュと既存の `YOUTUBE_API_KEY`・`YOUTUBE_CACHE` を共用し、新しい設定項目はありません。

RSSの直近分に対象がない場合は、取得済みの通常動画をAPIで再確認できた場合だけ「前回確認」として残します。片方のRSSが取得できなくても、もう片方は更新します。確認できる動画がなければチャンネルへのリンクを表示します。API全体の障害時は前回のデータを明示して残し、4時間後の閲覧から再試行します。

ことばの案内帳の「まずは、この6つから。」は、斎名智子アワーからWHITEBURNへの入口に変更しました。斎名智子アワーの用語本文・対談紹介は維持しています。

## ライブ予定とプレへそ特集

`/schedule/#live-events` は `/api/live-events` から公式イベントページ https://source-toma.earth/event/ をサーバー経由で取得し、日付順に表示します。年間一覧と個別公演の詳細をまとめ、重複を除いて日程・会場の追加や変更を反映します。開催日が本文のラベル付き項目にある場合は、古い見出しの日付より優先します。公演の削除・明示された中止も次回取得時に反映します。

既存の `YOUTUBE_CACHE` を共用し、4時間キャッシュ後の次の閲覧時に再取得します。表示中のタブも4時間を目安に確認します。無人の定時実行ではありません。YouTube APIは消費せず、追加のキーやKV設定は不要です。取得失敗や公式ページの構造変更時は前回確認した予定と確認時刻を残し、更新を確認できない旨を表示して4時間後に再試行します。公式ページの構造変更には抽出処理の調整が必要になる場合があります。

`content/live-events.json` の公演一覧は初回表示・障害時の予備情報です。ファン主催のプレへそ特集は同ファイルの `feature` で個別管理し、公式予定の自動取得では上書きしません。

日付は日本時間で判定し、開催日の23:59:59まで掲載、翌日0:00から非表示にします。プレへそは2026年12月23日0:00（日本時間）から特集枠全体が非表示になります。開きっぱなしでも日付をまたぐと反映し、タブ復帰・履歴からの復元時にも確認します。端末の時計が正しく設定されている必要があります。日付経過による非表示処理自体にはAPI・KVアクセスは発生しません。

古い静的HTMLが残っていても、日付を確認する前に終了済みの行が一瞬表示されないよう、日付付きの行と特集は初期状態を非表示にしています。JavaScriptを無効にした場合は公式イベント一覧へのリンクを利用できます。ビルド時にも終了分を除外します。

プレへそは主催者の記事から日時・会場・会費を要約し、詳細と申し込みは記事へリンクしています。確認時点の公式ページと記事は `research/official-events-20261118.*` と `research/preheso-20261222.*` に記録しました。

## 自動更新の仕組み

| 対象 | 取得方法 | 初回設定 | 更新の目安 |
| --- | --- | --- | --- |
| ファン17チャンネル | YouTubeの公開RSS | APIキー不要 | 30分のキャッシュ後、次の閲覧時 |
| 公式2チャンネルの公開済み動画（4欄で共用） | YouTube Data API v3 | 配信予定と同じAPIキー・KV | 4時間のキャッシュ後、次の閲覧時 |
| 公式2チャンネルの直近動画（各1本） | 公開RSS＋YouTube Data APIで公開状態確認 | 既存のAPIキー・KV | 4時間のキャッシュ後、次の閲覧時 |
| 公式2チャンネルの配信予定 | YouTube Data API v3 | APIキーとCloudflare KV | 4時間のキャッシュ後、次の閲覧時 |
| 公式サイトのライブ予定 | 公式イベントページの公開HTML | 既存のKVを共用・APIキー不要 | 4時間のキャッシュ後、次の閲覧時 |
| ご本人・スタッフ・推し活部の3ブログ | アメブロの公開RSS | APIキー不要 | 30分のキャッシュ後、次の閲覧時 |

YouTube・ブログ・ライブ予定とも、ページの閲覧をきっかけにサーバー経由で取得する方式です。誰も見ていない間に定時実行するものではありません。新しい動画の反映には、YouTube側の情報更新とキャッシュの時間がかかります。

ブログは `https://rssblog.ameba.jp/tomasource/rss20.xml`、`https://rssblog.ameba.jp/tomastaff/rss20.xml`、`https://rssblog.ameba.jp/osikatutoma/rss20.xml` が対象です。各ブログの公開日時の新しい順に3件を取得し、推し活部のトップ表示だけは最新2件に絞ります。本文や画像は転載しません。記事内のイベント日を予定として抽出する機能ではなく、記事タイトルに「本日」とあっても日付は記事の公開日です。アメブロのRSS反映に遅れがある場合もあります。

ブログの取得失敗時は前回の記事とその確認時刻を保持し、5分後の閲覧から再試行します。RSSが正常に空の場合は古い記事を消します。`YOUTUBE_CACHE` が設定されている環境ではブログ用の別キーでキャッシュを共有し、未設定ではWorkerインスタンス内のメモリーを使います。未設定時は拠点や再起動により30分以内でも再取得される場合があります。ブログにYouTubeのAPIキーは不要です。`/api/blogs` の `items`、`checkedAt`、`stale` で取得結果を確認できます。

ファンの一覧は動画の**公開日時**を基準にします。タイトル・説明の編集日時では並び替えません。RSSに掲載された最新の通常動画・配信が対象です。ショートはYouTubeがRSSに出す専用URL（`/shorts/`）で判別して除外し、動画の長さやタイトルでは判断しません。TOMA関連の内容だけに限定する仕組みではありません。取得できないチャンネルも消さず、前回の通常動画・配信やチャンネルへのリンクを残します。RSSの直近の掲載分がすべてショートの場合も、取得済みの通常動画・配信を「前回取得」と明示して残します。過去の通常動画が未取得なら、チャンネルへのリンクを表示します。

配信予定は、YouTubeが `upcoming` または `live` として返す公開動画が対象です。プレミア公開などもこの情報に含まれる場合に表示します。非公開・限定公開、YouTubeに登録されていない公演、検索への反映待ちは取得できません。現地ライブは、同じページの「今後のライブ予定」と公式の案内で確認できます。

取得成功で予定が0件なら、古い予定を消して「現在、確認できる公開予定はありません」と表示します。未設定や障害時には「確認済みの情報」「前回の情報」と区別します。開始から6時間を過ぎた予定は表示から外します。

## 配信予定・公式動画の自動更新を有効にする

一度設定すれば、配信予定と4か所の公式動画欄を自動更新できます。

1. Google Cloudで **YouTube Data API v3** を有効にし、APIキーを作成します。キーのAPI制限をYouTube Data API v3に設定します。サーバーから取得するため、ブラウザー用のHTTPリファラー制限は使いません。
2. CloudflareでKVの名前空間を作成します（例：`toma-youtube-cache`）。
3. Pagesプロジェクトの **Settings → Bindings → Add → KV namespace** で、変数名を **`YOUTUBE_CACHE`** にし、作成した名前空間を選びます。
4. **Settings → Variables and Secrets → Add** で、変数名 **`YOUTUBE_API_KEY`** にキーを設定し、種類を **Secret** にして保存します。キーはHTMLやソースファイルに書き込みません。
5. もう一度デプロイします。ProductionとPreviewは必要な環境それぞれに設定してください。通常はProductionだけで運用できます。
6. 公開サイトで `/schedule/` の確認欄が「YouTubeから自動取得」になれば有効です。公式動画欄では「公開済みの動画から自動取得」と表示されます。開発者ツールの通信結果で `mode: "api"`、`stale: false` を確認できます。APIのURLを直接開いても取得結果を確認できます。

APIキーとKVの両方がそろうまでは、配信予定・公式動画のAPIを呼びません。4か所の公式動画欄には、2026年11月17日に公開状態を確認した初期情報を「確認済み」として表示します。現在のZIPには、公開YouTubeで確認した2026年11月18日21時の配信を初期情報として収録しています。キー未設定でもサイトやファン動画・ブログのRSS更新は利用できます。

公式資料：[YouTube APIの開始手順](https://developers.google.com/youtube/data/getting-started)、[CloudflareのKV・シークレット設定](https://developers.cloudflare.com/pages/functions/bindings/)。

### 呼び出し回数

配信予定は、公式2チャンネル ×「公開予定・配信中」の4回の検索と動画詳細の照合を1セットにしています。公開済み動画は、2チャンネルを各1〜2ページ検索し、詳細でタイトルと公開状態を照合します。1ページ50件まで確認し、4欄を満たす新着動画が確定すればそれより古いページの取得を止めます。2ページでも確定できない場合は、前回の情報として表示します。

4つの動画欄は `/api/official-videos` の同じキャッシュを使い、閲覧ページごとには検索しません。結果はKVで共有し、公式動画・配信予定とも4時間保存します。継続して全機能を閲覧する場合、検索は通常1日約36回（追加ページが毎回必要なら約48回）が目安です。KVの拠点間の反映には時間がかかるため、同時アクセス時に重複取得する可能性があり、厳密な上限ではありません。取得失敗時にも4時間の間隔を置き、前回の動画と確認時刻を維持します。取得成功で0件なら古い動画を消します。

Google Cloudのクォータ画面で利用量を確認できます。別サイトやPreviewでも同じキーを使うと合算されます。最新の検索クォータは[YouTube公式資料](https://developers.google.com/youtube/data/reference/rest/v3/search/list)を参照してください。

## Cloudflare Pagesに公開する

通常は [GitHubのPR](https://github.com/morikyun/toma-oshikatsubu/pulls) で修正を確認してマージします。**Build and test** と **Deploy preview** の成功後、運営者morikyunのマージで本番公開が実行されます。現在のPagesプロジェクトを維持するため、GitHub ActionsからDirect Uploadを実行します。詳しくは [運用・初回設定](docs/GITHUB_WORKFLOW.md) を参照してください。

### ZIPをアップロードする場合

1. 同梱の `toma-oshikatsu-cloudflare-pages.zip` を使用します。
2. Cloudflareの **Workers & Pages** でPagesの直接アップロードを選び、プロジェクト名を指定してZIPをデプロイします。
3. 発行されたURLでホーム、`/videos/`、`/club/` を開きます。
4. 配信予定・公式動画も自動更新する場合は、上記のAPIキー・KVを設定して再デプロイします。

ZIPの最上位には `index.html`、`_worker.js`、`_routes.json` が入っています。`dist` フォルダーをアップロードしても利用できます。`_worker.js` はダッシュボードの直接アップロードに対応しています。[Cloudflare公式手順](https://developers.cloudflare.com/pages/get-started/direct-upload/)

ZIPの再作成は `npm run package`（Python 3が必要）。通常はGitHub Actionsがアップロードを担当するため、ZIPの手動更新は不要です。

### GitHub Actionsによる自動公開

`.github/workflows/pages.yml` が、PR時の検証・プレビューとmainへのマージ後の本番公開を担当します。公開物はチェック済みの `dist/` のみです。CloudflareのAPIキー・KVなどはダッシュボードの既存設定を使います。`wrangler.toml` 等は追加しません。

直接アップロードで作成したPagesプロジェクトをCloudflare標準のGit連携へ切り替える必要はありません。GitHubの `CLOUDFLARE_ACCOUNT_ID` と `CLOUDFLARE_API_TOKEN` で現在のプロジェクトへ公開できます。

`content/site.json` の `baseUrl` は `https://toma-oshikatsubu.pages.dev` に設定済みです。独自ドメインなどに変更する場合はこの値を変更して再ビルドします。canonical・OG URL・画像の絶対URL・sitemap.xmlを生成します。

## 構成と確認

- 本文は静的HTMLです。JavaScriptが無効でも案内文・リンク・用語・FAQを利用できます。確認済みの動画情報・画像・埋め込みもHTMLに含めています。新着取得・検索などはJavaScriptで補います。
- 動画は自動再生しません。直近の公式動画は埋め込み表示し、その他の動画はリンクからYouTubeが別タブで開きます。サムネイルはYouTubeの画像配信元から読み込みます。

- 独自のアクセス解析・広告・Cookieは使っていません。表示設定のlocalStorageは使用しません。Cloudflare等の外部サービスの処理はプライバシーポリシーで説明しています。持ち物チェックはページを開いている間だけ保持します。
- 元資料や検証メモは `research/` に保存し、GitHub・公開用の `dist/`・ZIPには含めません。
