# TOMA推し活部 — はじめてのとおま案内

總水とおまさんを応援する非公式ファンコミュニティのサイトです。生成り・ネイビー・淡い紫を基調に、スマートフォンでも読める構成にしています。

[サイトを見る](https://toma-oshikatsubu.pages.dev/) · [修正・新しいページをお願いする](https://github.com/morikyun/toma-oshikatsubu/issues/new/choose) · [用語の意味を知る](#はじめてのgithub用語案内)

## 修正・新しいページのご相談

「ここを直してほしい」「こんなページがあると嬉しい」という声をお待ちしています。**ITの知識は必要ありません。いつもの言葉で教えてください。**

GitHubでは、このような依頼を **Issue（イシュー）** と呼びます。サイトへのご要望を運営に伝える「連絡票」のようなものです。

### まず、お願いしたいことを選びます

フォームを選ぶと、依頼の種類を表す**ラベル（色付きの付箋）が自動で付きます。** 迷ったときは「質問・相談したい」を選んでください。

- **[文章・名前・リンクを直したい](https://github.com/morikyun/toma-oshikatsubu/issues/new?template=01-change.yml)**：紹介文や名前の修正、リンク先の変更、情報の追加など。ラベルは「説明文・案内」。
- **[新しいページを作ってほしい](https://github.com/morikyun/toma-oshikatsubu/issues/new?template=02-new-page.yml)**：まだサイトにないページの提案。ラベルは「改善・追加」。
- **[表示がおかしい・リンクが開かない](https://github.com/morikyun/toma-oshikatsubu/issues/new?template=03-problem.yml)**：文字が重なる、ボタンが反応しないなど。ラベルは「不具合」。
- **[見やすく・使いやすくしてほしい](https://github.com/morikyun/toma-oshikatsubu/issues/new?template=04-usability.yml)**：文字の大きさ、色、配置、操作のしやすさなど。ラベルは「見やすさ・使いやすさ」「改善・追加」。
- **[機能を追加・改善してほしい](https://github.com/morikyun/toma-oshikatsubu/issues/new?template=05-feature.yml)**：検索や絞り込み、予定の保存など、できることを増やす提案。ラベルは「改善・追加」。
- **[質問・相談したい](https://github.com/morikyun/toma-oshikatsubu/issues/new?template=06-question.yml)**：サイトの内容や使い方の質問、まだまとまっていない相談。ラベルは「質問・相談」。

### 登録のしかた

1. **上のリンクからフォームを開きます。** ログインを求められたら **Sign in（ログイン）** へ進んでください。GitHubのアカウントがない方は **Sign up（アカウント作成）** が必要です。ログイン後、もう一度上のリンクを開くとフォームに進めます。
2. **タイトルを書きます。** 例：「ファンのYouTubeの紹介文を変えたい」。最初から入っている `[修正]` などの後ろに、お願いしたいことを短く足してください。
3. **質問に沿って入力します。** 必須の項目だけでも送れます。URLが分からなければ空欄で大丈夫です。画像は文章を書く欄に貼り付けるか、欄の下の添付ボタンから追加できます。
4. **画面下の「Create（作成）」または「Submit new issue」を押します。** 登録できると、依頼のページが開き、「#3」のような番号が付きます。そのページのURLを控えておくと、あとから確認できます。

GitHubの上部メニューからは **Issues → New issue** でも同じフォームを開けます。スマートフォンなどでは、メニューが「…」の中にあることもあります。

### 修正依頼の記入例

- **どのページ？** ファンのYouTube
- **どの部分？** 自分のチャンネルの紹介文。いまは「〇〇について発信しています」と書かれているところ。
- **どう変えたい？** 「總水とおまさんのライブの感想や、日々の気づきをお話ししています」に変えてほしい。

新しいページなら、**「どんなページか」「誰に何を伝えたいか」「載せたい内容」** を教えてください。文章や見た目がまだ決まっていなくても、「相談したい」と書いてもらえれば大丈夫です。

### 登録したあとは

運営が依頼を確認し、必要があればそのページのコメント欄でお聞きします。補足や訂正もコメントに書けます。対応内容を確認してからサイトへ反映するため、登録と同時にサイトが変わるわけではありません。依頼した方がサイトのファイルを編集する必要はありません。

入力した文章や画像は、誰でも見られる状態で公開されます。電話番号・住所・パスワードなどは書かないでください。

## はじめてのGitHub用語案内

聞き慣れない名前も、身近なものに置き換えると少し分かりやすくなります。ここでは、このサイトでの使い方に沿ってご紹介します。

### GitHub（ギットハブ）とは？ — みんなで使う「資料室と作業場」

サイトの材料となる文章やプログラムを保管し、修正の相談や変更の記録をまとめられるインターネット上のサービスです。みんなで会報を作るときの、原稿を置く棚と、相談用の掲示板が一緒にある場所をイメージしてください。

推し活部では、サイトの資料をここに置き、「ここを直してほしい」という声も受け付けています。普段の言葉で相談できます。

### Issue（イシュー）とは？ — お店に渡す「ご要望カード」

「何に困っているか」「どうしてほしいか」を、一件ずつ書いて相談する場所です。お店のご要望カードに「この商品を置いてほしい」と書くように、「このページの紹介文を変えてほしい」と伝えられます。

たとえば「ファンのYouTubeにある私の紹介文を、この文章に変更してほしい」という依頼が一つのIssueになります。登録すると専用のページと番号が付き、同じページで補足や質問をやり取りできます。

### Pull Request（プルリクエスト／PR）とは？ — 印刷前に見てもらう「確認用の原稿」

作業した人が、実際に直した内容を見せて「この変更を取り入れてよいですか」と確認をお願いするものです。会報の原稿を直したあと、印刷する前に担当者へ見てもらう場面に似ています。

先ほどの例なら、紹介文を直した人が「この文章に変更しました。確認してください」とPRを出します。運営者は変更内容を確認し、必要なら直してもらってから採用します。**Issueは「こうしてほしい」という依頼、PRは「こう直しました」という変更案**と覚えると分かりやすいです。

### 依頼がサイトに反映されるまで

1. **Issueで依頼する**：「紹介文を変えてほしい」とご要望カードを渡します。
2. **担当者が修正し、PRを出す**：直した文章を確認用の原稿として提出します。
3. **運営者が確認してマージする**：内容に問題がなければ、正式な内容として採用します。
4. **サイトに反映される**：このサイトでは、マージ後の自動チェックが成功すると公開されます。

依頼する方は、まずIssueを書ければ大丈夫です。補足が必要なときは、運営がコメントでお聞きします。

### ほかに見かける言葉

- **README（リードミー）**：今読んでいる、この案内文です。お店の入口にある「ご利用案内」のように、この場所の目的や使い方を紹介します。
- **リポジトリ**：一つのサイトや活動に関する資料・記録をまとめる場所です。GitHubが資料室なら、推し活部専用の棚がこのリポジトリです。
- **ラベル**：依頼を分類する「色付きの付箋」です。このサイトでは、選んだフォームに応じて「不具合」「質問・相談」などの目印が自動で付きます。運営が内容を確認し、あとから調整することもあります。
- **コメント**：依頼や変更案のページに書き足すメッセージです。連絡帳の返事のように、質問・補足・訂正をやり取りできます。
- **マージ（Merge）**：確認した変更案を正式な内容に取り込むことです。修正した原稿にOKを出して、正式版に差し替えるイメージです。このサイトでは運営者が行います。
- **クローズ（Close）**：その依頼や変更案に区切りを付けることです。連絡票を「対応済み」や「今回は見送り」として片付けるイメージです。閉じた理由はコメントなどで確認できます。
